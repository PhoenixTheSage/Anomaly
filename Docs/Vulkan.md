# Vulkan guest bus

Anomaly is the pack host on Keen DX11 and on SE-Vulkan. Packs keep `Fullscreen/<Slot>`, `anomaly.json`, `SetUniforms`, and catalog names. The backend is chosen once, when the operational renderer exists. A missing SE-Vulkan assembly at plugin init stays pending until `MyProgram.m_renderer` is `MyDX11Render`. `RequestedBackend` is not the session. A second, different choice is recorded and does not switch the loaded assembly. The other path stays unloaded.

## Assemblies

| Assembly | When it loads | What it owns |
|---|---|---|
| `Anomaly.dll` | Always. This is the Pulsar plugin. | Registries, pack scan, terminal pages, the HLSL bus, and the settings dialog (`Anomaly.cfg`). No `VRage.Render11`, no SharpDX, no Keen patches. |
| `Anomaly.Dx11.dll` | Only after the live renderer is `MyDX11Render`. Beside the plugin, or the plugin's `ClientPlugin\bin` build when Pulsar source mode compiled the core into `DevFolder`. Not an `IPlugin`, and not a second Pulsar plugin. | Today's Harmony patches, SharpDX compiles, and `MyManagers` textures. |

Pulsar source mode compiles every `.cs` file under `Anomaly.xml` `SourceDirectories` into `Anomaly.dll`. Those directories are `ClientPlugin/Backend` and `ClientPlugin/Settings`. `Settings` is where Pulsar reads `[assembly: AssemblyVersion]` and where `Anomaly.cfg` loads, including on Vulkan. The DX11 sources stay in the rest of `ClientPlugin` and are built by MSBuild as `Anomaly.Dx11.dll`. `Settings` is compiled into that assembly too. The two copies are different types and cannot share one Pulsar compilation. On DX11 the device patches read the DX11 `Config`; the Pulsar dialog edits that copy once `Anomaly.Dx11` is loaded. A Vulkan recovery launch is that DX11 path. Source mode's `DevFolder\...\Bin` does not contain the satellite, so the lookup also checks the plugin's `ClientPlugin\bin` output for the running runtime and then Pulsar `Local`. The same lookup loads `SpaceEngineersDLSS.Dx11.dll`, `SpaceEngineersFRS.Dx11.dll`, `SpaceEngineersFrameGen.Dx11.dll`, and `HdrOutput.Dx11.dll`. If the satellite is still missing, Anomaly opens the core settings dialog and the DLSS/FRS anti-aliasing lists keep their fallback items.

SE-Vulkan's compatibility check still fail-closes on a direct `VRage.Render11` or `SharpDX*` reference. Anomaly is not on the known-consumer list. An older Anomaly build that still references those assemblies still forces DX11. SE-DLSS, SE-FRS, SE-FG, and HdrRender keep those references in a sibling `*.Dx11.dll` that loads only on Windows DX11. Their main assemblies request renderer services on Vulkan: DLSS asks the renderer to evaluate driver NGX when `nvngx_dlss.dll` is beside the plugin, FRS asks the renderer to evaluate FSR 3.1.4 when `amd_fidelityfx_vk.dll` is beside the plugin, frame generation asks the renderer to run the same bidirectional warp as DX11 and present that frame immediately, and HDR asks for an FP16 swapchain. The temporal upscale is the Catmull-Rom fallback. It is not NGX and not FSR. DX11 FRS stays on FSR 2.2.1. FSR 4 is not used; that SDK dropped Vulkan. DLSS headers stay out of git; the renderer binds `NVSDK_NGX_VULKAN_*` from the driver's `_nvngx.dll` the same way the DX11 plugin binds `NVSDK_NGX_D3D11_*`. Aurora, Volumetric Clouds, Screen Space Shadows, Final Frontier, and Prism.SSGI allocate through the catalog. Prism's DX11 SVGF stack is `Prism.SSGI.Dx11`. On Vulkan the same temporal, moments, and à-trous passes run on the guest bus and DirectAdd into world HDR. SE-RT's software ray backend is `SERT.Dx11`, loaded only on Windows DX11. Its hardware path is the renderer ray-query export.

Linux loads a pack only when Anomaly has opened the Vulkan guest bus. DX11 device work, Harmony against `MyRender11`, and SharpDX stay closed. A Linux session whose route is still pending or DX11 stays idle.

`IgnoresAccessChecksTo("VRage.Render11")` is a string attribute. It is not a reference.

## Renderer route

Packs read `ClientPlugin.Backend.RendererRoute` by reflection. It is the operational renderer, and it is readable before that choice exists.

| `Active` | Name | Shared bus | DX11 device | Vulkan guest |
|---|---|---|---|---|
| 0 | pending | open | closed | closed |
| 1 | DX11 | open | open | closed |
| 2 | Vulkan | open | closed | open |

`UseSharedBus`, `UseDx11Device`, and `UseGuestImages` are the path flags. `IsPathOpen` takes `shared`, `dx11-device`, or `guest`. `Decided` is false while `Active` is 0. `LastRefusal` records a blocked device call. A DX11 call such as `DrawFullscreen`, `PublishedBuffer.Srv`, `OwnedPassRegistry` device work, `FrameTemporal`, the celestial registry, or the shared-volume registry does not run on Vulkan or while the choice is pending. `ShaderPackRegistry.Register`, `OwnedPassRegistry.Register` / `Unregister`, and `FullscreenPassRegistry.SetEnabled` issued from `LoadAssets` are held and applied when DX11 commits, after the json programs exist. A Replace left at its json default until that checkbox lands overwrites the lit scene. Vulkan discards the DX11 hold. A guest image is not allocated on DX11. Catalog `PublishRgba8` and volume uploads stay on the shared bus: they keep the bytes and bind the device that wins. Do not read SE-Vulkan `RequestedBackend` or `BackendRuntime` to choose a path.

Packs copy `AnomalyRenderer` (same reflection body, the pack's own namespace). It reads `RendererRoute` with no compile reference to Anomaly. `Register`, `SetUniforms`, and `PublishRgba8` stay on the shared bus. Device work waits:

```csharp
if (!AnomalyRenderer.Decided)
    return;

if (AnomalyRenderer.UseDx11Device)
{
    // Rc, Srv, OwnedPassRegistry, FrameTemporal, celestial draws
}
else if (AnomalyRenderer.UseGuestImages)
{
    // catalog images and fullscreen packets
}
```

## Guest packet

Before the frame ends, Anomaly submits copied pass packets: slot, SPIR-V, reflected bindings, uniform bytes, sampled and storage image ids, compose mode. Native replays them on the render thread. Managed code does not record a `VkCommandBuffer` and does not touch `MyRender11.DeviceInstance` during a Vulkan session.

ABI stays version 1. The guest exports and `SevkGuestPass` (416 bytes, natural alignment) are additive. Register bands `b/t/s/u` at 0/128/256/384 match the fullscreen bus (`t0–t13`, `b6` extras, `b7` uniforms).

A pipeline is created for the fixed bus: `t0–t13`, `s0–s2`, `b6` extras (320 B), `b7` uniforms (256 B), owned `b0` (at most 256 B) or the exact stock `Frame.hlsli` layout (1280 B), storage buffers at `t1` and the pack/light slots `t7–t13`, and compute `u0`. Native borrows the current world frame's point-light/tile buffers at t10/t11 when no catalog override is supplied. A binding outside that set rejects the pipeline with a visible failure. An empty packet records no draws. `guest_replay` still runs at the six marks.

Guest compilation runs in the frame callback after the native bridge is bound and Anomaly assets are available. Late registrations and a temporarily absent renderer retry; compiled SPIR-V survives that retry. Generated sources live in a dedicated directory, so the compiler never snapshots the entire system temp tree. Include roots cover Anomaly, the pack and its `Inject` directory, and the installed game's shaders. Slot defines match DX11. Driver-facing modules go through SE-Vulkan's existing `SpirvRuntimeModule.Prepare`; compiler reflection annotations stay in the cached artifact. Shader and native-pipeline failures retain their diagnostics instead of becoming permanent silent deferrals.

Manifest `binds` and `priority` are honored. At each mark, owned producers precede pack consumers, then pack priority and registration order determine execution. Scene dimensions/camera/sun come from the guest frame before image allocation. Hi-Z is a half-resolution 2×2 minimum of linear depth. Linear depth ping-pongs under `linearDepth`/`historyDepth`; first-frame and resized history remain unpublished until initialized. Current catalog aliases follow the write image on every frame. History color copies HDR at AfterUpscale, after this frame's consumers have sampled the previous copy. Resizing reuses image ids and waits for native users before replacing the old allocations.

IsolatedAdd, IsolatedMix, IsolatedSub, DirectAdd, Chain, and Replace composite onto the world HDR target. PublishOnly and compute write the named catalog image and `pass.{id}`. The world target is not cleared. `passes[].scale` and `SetScale` snap to 1, 0.5, or 0.25 on Vulkan the same way they do on DX11. `passes[].history` ping-pongs two images and catalogs the previous one under that name before the pass draws. Sampled ids in the top of the `uint64` range are renderer images, not guest allocations: HDR, depth, the three GBuffer colors, the upscale image, and the display image. `sevk_get_guest_frame` is 344 bytes. The first 328 bytes are the sun, view, and resolution the extras constant buffer uses. The tail is `far_plane`, `output_width`, `output_height`, and `service_flags`. `FrameTemporal.FarClip` reads the far plane. `AnomalyCameraToWorldPad.x` carries the same far value inside the 320-byte extras buffer. `DisplayServices.Request` sets service bits without clearing the others: 1 HDR swapchain, 2 the bidirectional frame-generation warp plus its extra immediate present, 4 the renderer temporal upscale. Bit 8 is set in the returned flags when the surface actually opened an FP16 extended-sRGB swapchain.

| Mark | Value | Where |
|---|---|---|
| AfterLighting | 1 | After deferred lighting, before the environment |
| AfterAtmosphere | 2 | After the environment, before flares |
| AfterTransparent | 3 | After transparency, before the HDR-to-SRV barrier |
| BeforeTonemap | 4 | Start of postprocess |
| AfterTonemap | 5 | After the tone stage, or immediately when post is disabled |
| AfterUpscale | 6 | After world compose, before HUD sprites |

C# owned-pass slots are 0–5. The native mark is the value in this table, chosen by slot name. Do not pass the C# enum ordinal as the mark.

Compose values: IsolatedAdd 0, IsolatedMix 1, IsolatedSub 2, Chain 3, Replace 4, PublishOnly 5, DirectAdd 6.

## Catalog images

### Shared volume resource transport

Feature 2048 adds GuestBridge.ConfigureDepthViews(imageIds, cameraRelativeMatrices) and DepthViewsReady. Requests must be configured before BeginFrame and use up to three allocated kind-7 D32 images. Classic world-packet reserved bits 8–10 select those views independently of the eight stock cascade bits. Projection slots 73–75 follow the stock/spot range. The native owner uses each target's dimensions and regular depth-material shaders, clears forward depth to 1 and records the views before GBuffer and guest consumers.

Requests are consumed once; DepthViewsReady is a recorded-view mask that resets at BeginFrame, not GPU completion or a proof of source coverage. Tests/GuestDepthGpuTests verifies the production rigid depth path and coexistence with eight stock views. The separate scene collector and frame owner now supply the early requests and activation/commit transaction; broader geometry and loaded-world acceptance remain pending.

The actual host callback runs after native BeginFrame and before EndFrame. Feature 1024 permits guest pipeline/image creation in that allocation window; EndFrame closes it before recording world and guest draws. Image replacement still waits for prior submissions and API calls share the renderer mutex. Anomaly refuses older native libraries with an update diagnostic. This is a capability bit, not an added pass flag.

Tests exercise factories, image upload/replacement and copied packet submission inside a real open menu frame, then replay the created resources and check their pixels. This covers the live resource phase that offscreen ReplayNow alone missed; queued-world insertion, loaded-world output and recreation remain separate acceptance work.

VolumeRegistryState is the shared device-free CPU contract. FacadeVolumes retains pending registration/configuration/requests and replays them after companion initialization if DX11 commits. Vulkan uses the same copied parameters, double origins/bounds, revisions and interval callbacks. The shared shader composer and airtight-room snapshot live under Backend so Pulsar includes them in the core source manifest. VolumeInteriorData packs the same sorted signed cells and seven-row grid records for both runtimes; DX11 keeps ownership of its SRV allocations.

Guest frame start resets interval callbacks and removes all five volume products before resetting the native pass queue. Callback or bridge-reset failure leaves volume readiness false; registration and compiled kernels do not acquire a near interval. Late fallback-present creation follows the provider enabled state, and re-registration after removal replaces its source. The separate CPU companion fixture exercises pending replay through the real reflection bridge and production registry source. This is not shared-renderer activation.

Feature bit 512 gates GuestBridge.CreateExtendedPipeline and SubmitExtended. Pipeline resource contract 1 accepts t0–t47, b0–b7 (at most 4096 bytes each), s0–s5 and compute u0–u4. Contract 2 reconstructs into two RGBA16F targets. The extended sampler order follows the shared shaders: s0 linear clamp, s1 linear wrap, s2 point clamp, s5 clamp comparison LESS_OR_EQUAL. This is separate from the original fullscreen sampler order. Native reflects XYZ workgroup sizes; packet width/height/depth are invocation counts.

SevkGuestPass2 is 568 bytes with version 2: size/version/mark/compose/width/height/depth/flags at 0–31, pipeline at 32, 48 sampled IDs at 40, five outputs at 424, eight constant pointers at 464 and their byte counts at 528; final eight bytes are reserved zero. Native copies all constant payloads before returning. Flag 16 zero-clears used compute outputs. Extended draws are submitted by their owned producer rather than the generic fullscreen loop. Missing support stays retryable with a capability diagnostic. The 416-byte ABI-1 packet remains unchanged.

Image kind 7 is sampled D32 depth; kind 8 is R16F. Base-level readback includes all depth slices/array layers and returns native 2/4/8/16-byte texels. Shared-volume HLSL uses explicit FP16 storage formats under the guest compiler's ANOMALY_SPIRV define, and native validates reflected storage formats and image dimensions before accepting a packet. Missing resources/constants, aliases and duplicate outputs reject the packet. Frame-fence retirement, uniform alignment and compute/fragment/transfer dependencies apply to every output.

The production shared-volume kernels now compile and execute through this transport in the strict GPU fixture. The frame owner described below now connects directional shadows, resources, interior buffers, history, interval commit, HDR composite and motion. The bounded legacy march remains the fallback when that complete transaction is unavailable. See the volumeReactive acceptance scope in the parity notes.

`RequestPointShadows` and `RequestWorldBoxes` retain requests before renderer selection. Anomaly owns an RGBA32F six-face character atlas and render-sized R32F `playerDepth`. `GuestBridge.CaptureCharacter` returns copied opaque indexed geometry with the stock four-bone homogeneous skinning equation, stable atlas LOD/current mask LOD, double world matrix and bounds. Atlas transforms subtract each light origin in double precision and ignore main-view hiding flags. Header light/range and caster validity follow the DX11 sampling contract. Optional world boxes retain the shared exclusions and work limits. Missing inputs/native support unpublishes both images; an absent controlled character produces far clears and invalid caster headers.

ABI-1 feature flags 64/128/256 provide geometry draws, viewport/scissor and far clears. The geometry pipeline uses vertex entry `geometry_vertex`, procedural structured-buffer vertices, MIN blending and image kind 6 (RGBA32F). Copied b0 contains ViewProj at byte 0, World at 64, float4 viewport at 128 and uint vertex/mesh/box counts at 144. Native validates viewport/counts before rendering; LOAD preserves previous cube faces and header draws. Far clear is 100000. Native readback returns native texel bytes (4/8/16). The point-shadow GPU fixture uses the production owner, independent face/mask distance oracles, animated poses, world boxes, observer movement and the real pack sampling helper. Live geometry, recreation and performance acceptance remain pending.

`RequestOccupancy` retains demand before renderer selection. The owned AfterLighting group reuses `OccupancySplat.hlsl` and `OccupancyStamp.hlsl` for a cleared 512×512, 64³/2 m camera-relative atlas (R32F on Vulkan, R8 on DX11). It requires this submission's linear-depth producer; retained previous-frame aliases cannot satisfy it. Anomaly selects lights and bounded AABB stamps from copied renderer scene inputs, excludes the local character/light owner, retains stable incumbent selection and subtracts camera positions in double precision. The selected cap/face request also drives the character atlas described below. No request or missing dependencies unpublishes occupancy.

Native ABI-1 flags 16/32 clear compute storage and copy the packet constants into b0; t0 accepts the box storage buffer. Workgroup sizes come from SPIR-V rather than assuming 8×8, and transfer/compute writes become visible to fragment and compute consumers. The guest uniform allocator queries device alignment without depending on stock world initialization. Structured guest uploads use per-frame buffers protected by the same fences as guest uniforms/descriptors; the third slot is synchronous offscreen replay. `GuestBridge.CaptureShadowInputs(uint localActor)` returns copied double light xyz/range records, light actor IDs, double center/half-extents, box actor IDs and anchor/camera positions. This is scene transport, not a second pack registry. See `Tests/GuestRuntime` for whole-atlas GPU readbacks and exact evidence limits.

`BufferCatalog.RequestLitMips` and `FullscreenPassRegistry.RequestLitMips` retain demand before renderer selection and use the same sticky maximum as DX11 (2–12 levels; zero clears). Enabled pipeline-ready `litMips` binds request five levels automatically. The Anomaly-owned AfterLighting packet publishes `litMips` at render resolution, copying current HDR to FP16 then generating the chain before pack consumers. Actual mip count is clamped to image dimensions. Demand removal clears the alias; size/level changes use the guest image's idle-protected recreation. SE-Vulkan advertises packet flag 8 through `sevk_guest_features` and `GuestBridge.SupportedPacketFlags`; older libraries leave the product unavailable with an update diagnostic. Transfer dependencies expose every generated level to fragment and compute sampling. See the lit-mip GPU readback in `Tests/GuestRuntime`.

`PublishedBuffer.Publish(object, IntPtr, int, int)` stays as it is. Both the DX11 type and the core facade add `PublishRgba8`, `PublishVolumeRgba8`, `PublishStructuredFloats`, and `PublishVolumeMips`. `BufferCatalog.Active(name)` stays `object` plus `IntPtr`. On DX11 the active value is the inner buffer, so `.Srv` still exists.

On Vulkan, CPU-backed uploads retain cloned payloads and rebuild after ResourceEpoch changes. Structured floats require a positive four-byte-aligned stride that divides the payload size. Device-end callbacks run before restoration; failed callbacks block guest submission for retry. Retained GuestRendererImage wrappers become unavailable when their owning context ends. Celestial structured data and array textures follow the same restoration policy. The actual-core hardware lane verifies restored bytes through typed GPU reads after context destruction/recreation, then verifies fresh volume, occupancy and spectator shadow output.

Owned passes that the bus samples — linear depth, Hi-Z, history color, reactive mask, lit mips, and camera velocity — publish under the same catalog names. On Vulkan those are fullscreen programs (`CameraVelocity.hlsl`, `LinearDepth.hlsl`, `HiZDownsample.hlsl`, `HistoryCopy.hlsl`, `ReactiveClear.hlsl`). On DX11 the existing owned-buffer pass still publishes them. Vulkan object motion is an RG16F image written by a depth-equal geometry pass (rigid, generic, cube, and deformed cube). `CameraVelocity.hlsl` keeps those pixels and fills the rest from depth. Catalog `velocity` is the `CameraVelocity` result at guest image `0xFFFF00000000000A`: object motion where the geometry pass wrote it, camera reprojection from depth everywhere else. Frame generation samples that image when `history_valid` is set, with `mv = output / velocity size`, and seeds instead of warping when `FrameTemporal.InvalidateHistory` clears history. Without the image it keeps the renderer object-motion buffer. `volumeReactive` is guest image `0xFFFF00000000000B` when a program publishes that catalog name; the warp uses it as the DX11 reject mask. The shared froxel producer now queues this mask on Vulkan when its complete transaction succeeds.

Cloud shape and detail volumes are 128³ and 64³ with a CPU box-filter mip chain. `PublishVolumeMips` uploads that chain; the guest image keeps every mip. Weather is uploaded as 64×64×2, matching the production pack. Storms are 128 floats at structured stride 16 and stay a structured buffer; PublishedBuffer uploads bind as guest storage buffers.

Catalog `hdrColor`, `upscaledColor`, and `displayColor` are renderer images. `ClaimUpscale` records the pack and tells the renderer the owner. Bilinear compose stays the default until that owner evaluates. AfterTonemap (mark 5) samples and merges into the tonemap image, the same LDR result DX11 passes to SE-DLSS after Anomaly's postfix. When the owner is `se-dlss`, the renderer evaluates that image there and publishes the dest as `upscaledColor`. AfterUpscale (mark 6) then samples and merges into that dest, before compose. Vendor SDK calls stay in HdrRender, DLSS, FSR, and frame generation. Anomaly owns `pointShadowAtlas` and `playerDepth` through the geometry packets described above.

`RequestSrv` on Vulkan fills `t7–t9` and `t12–t13` from catalog names. After tonemap, `t4–t6` are `avgLuminance`, `bloom`, and `dirt`. The renderer publishes these as images (exposure, the bloom chain result and the dirt texture) that are valid once the frame's tone stage has run. Portable `TonemapInputs.Grading` carries the postprocess grading values, and `RenderClock.FrameSeconds` the render draw time.

`VolumetricMediumRegistry.Register` on Vulkan compiles the provider into one compute packet at AfterAtmosphere. The three catalog volumes, including their mip chain, are `t11–t13`. A following IsolatedAdd samples that image. The DX11 froxel stack uses extra UAVs and a provider constant buffer that do not fit this bus, so the guest march is 12 bounded steps of `EvaluateMedium`. `CelestialBackgroundRegistry.Register` is a depth-tested Replace at AfterLighting. `SetNativeSunGlare(id, false)` drops stock directional glare once that draw has a pipeline. Art is a 2D array image. Structured celestial data is a storage buffer at `t1`.

## Status

Show Status and Velocity Status keep the DX11 section labels when the DX11 report is not loaded. Compile status separates ready, pending, failed, and submitted program counts. Submitted means the managed packet was sent; it is not GPU execution proof. A connected frame bus does not certify GBuffer writes. Published velocity distinguishes the submitted catalog program from the renderer motion fallback. `GBuffer attachments: none` counts extra pack attachments, and pass binds count explicit manifest/runtime bindings; standard GBuffer t4–t6 remain automatic.

`Tests/GuestRuntime` uses the real SE-Vulkan compiler and production submission/catalog-routing code. `--packs` adds the installed sibling SSGI, clouds, aurora, contact-shadow and Final Frontier sources. `--gpu` requires real native pipeline creation and a stock-frame/UV pixel readback; unlike an optional smoke lane, missing GPU support fails. The submission/catalog fixture uses a recording bridge, so passing it does not claim in-world visual parity. See its README for commands and limits.
