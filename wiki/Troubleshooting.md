# Troubleshooting

In-game: Anomaly settings → Show Status. Also `SpaceEngineers.log` and Anomaly’s debug log. Compile errors include `pack=id`.

> **Constant-buffer binding:** The logical VS b6 and PS b7 layouts remain 224 and 16 bytes, while both dedicated physical buffers are 256 bytes. The 14/1 D3D11.1 range fix was legal at 16/16 but did not change the probe result. Current builds deliberately use ordinary whole-buffer binds at the exact native draw boundary, clearing inherited range state; Debug Status must report nonzero `whole-binds(256/256)`. With `MrtWrite`, `Native draw state` verifies the actual native VS, PS, b6, b7, and Target3 identities for every draw; each `m/n/x` triplet means match/null/mismatch.

## Status fields that matter

Use **Show Status** for routine operation and **Debug Status** for the motion-vector audit. Debug Status is grouped into screenshot-sized `[PASS]` / `[WARN]` checks instead of exposing every raw counter.

- `Compile` and `Include`: interception/refresh succeeded and Anomaly won the GBuffer include resolution.
- `Compile endpoint`: compiler calls and full-flow results, including calls outside an active Init (`orphan`). Unowned calls do not prove failure or belong to the next object. Their bounded call stacks and missing-flow identities go to SpaceEngineers.log even in Release. Counts need not equal Init counts.
- `Object repair`: attempts, verified replacements, failures. At Init return, unverified GBuffer objects are compiled through the common endpoint without forced cache invalidation. Only fully verified replacements are installed, before publication to Keen; vertex input-layout bytecode is replaced with the same array. Failure preserves the original. Original bad bytecode remains in historical DXBC counters, so those can warn after a successful repair. The draw-contract summary instead requires verified resident objects and all observed drawn pairs, and is explicitly not proof of motion math.
- `Object proof` and `DXBC VS/PS`: every native velocity object has its own bytecode evidence, and executable b6/TEXCOORD12/b7/Target0/3/7 flow is present.
- `CPU Stage2` and `CPU motion`: ActorID history was packed in instance order and includes nonzero transforms.
- `MRT`, `CB binds`, `Draw target`, and `Blend`: Target3 and dedicated b6/b7 buffers are live, whole-bound, writable, and restored correctly.
- `Native CB`, `Native shader`, and `Native RT`: queried match/null/mismatch triplets for the exact draw state.
- `Draw VS/PS` and `Pairs`: resident classification and exact VS+PS proof at draws. A very low `full/seen` count with complete object proof points to draw-pair lookup; incomplete object proof points to shader-object evidence association.

The raw counters remain available in the log. `hook=0` still means the old-pipeline transpiler never ran, and Stage 2 values remain last-drawn so menu frames do not erase useful evidence.

`visible=0` means no Stage 2 instances on Main (character/drone are old-pipeline — read the Old-pipeline line). `V/S` like `833/833` means t15 packed with ActorID history. `drew=` is groups present at `MyGeometryRenderer.Render`. `groups=` / `base=` are InstanceBase binds (`base` is the last `OffsetInInstanceBuffer`). Pause/menu Prepare used to publish `groups=0` while keeping `833/833` — that is not a dead bind. A paused overlay is mid-grey even when pack is correct — look while moving.

Raw-probe ladder: `GBufferVelocityRaw + TargetClear` verifies the pre-pass clear. `MrtWrite` clears to -X/cyan and forces +X/pink at the final GBuffer PS output through runtime PS b7; its exact-boundary four-RT/CB bind is mirrored into Keen's state tracker, repeated natively, and restored at pass end. Together with the velocity-safe blend override, that removes shader-cache identity, stale output-merger state, leaked Target3 bindings, and masked writes as ambiguities. Status `draw-boundary=before/checks->after restores=N` reports the tracker before and after the exact-boundary bind plus completed pass restores. Gray geometry means the shader explicitly wrote zero; matching sentinel-colored regions are paths that did not write Target3. `PassEndClear` issues +X once on Keen's immediate context after `MyRenderScheduler.Done` executes every deferred geometry list. It is the final resource-identity test: all depth-foreground pixels must be pink and status must show `pass-end-clear=1`. `HistoryCoverage` then proves native VS b6/t15 and separates previous-world hits from misses. `Off` finally tests the actual transform math without the camera fallback concealing raw zero. All transitions are immediate and require no menu trip or shader refresh; only the startup overlay activation queues one Keen-owned refresh.
